Why idx

Built for how developers actually search

grep and ripgrep are great at finding strings. idx is built to find relevant code.

🎯

Relevance ranking

BM25 scoring with a filename-match bonus. Files whose names contain your query term always surface first — even if the content score is lower.

⚡

Instant results

Searches a pre-built inverted index, not raw files. No disk scanning at query time. Sub-millisecond lookups even in large monorepos.

🔒

Offline & private

Everything runs locally. No telemetry, no cloud indexing, no data leaving your machine. Works without a network connection.

🔬

Precision filters

Narrow searches by file extension (--ext go) or path prefix (--path internal/core). Combine AND / OR with relaxation fallback.

🔄

Always fresh

Run idx daemon enable . once and the index updates in real time as files change — no manual syncs needed during development.

📖

Read-aware ranking

idx read <file> logs every file access. Files you open frequently get a ranking boost in future searches — the index learns your workflow.

Quick start

Up and running in three commands

Requires Go 1.26+ and a Git repository.

1

Build & install

Clone the repo and build the binary. Add it to your $PATH.

2

Index your project

Run once per project. Builds the BM25 index for every directory.

3

Enable background sync

The daemon watches for file changes and keeps the index up to date automatically.

4

Search

Use AND / OR logic, path filters, and extension filters to narrow results.

zsh
# 1. build $ make build && cp bin/idx /usr/local/bin/   # 2. index your project $ idx init ✓ indexed 847 files in 312ms   # 3. enable background sync $ idx daemon enable . ✓ daemon started (pid 48291)   # 4. search $ idx search "rate limit" --ext go internal/core/services/search/limiter.go 0.97
