# v0.11.0 — Agent-optimized Output

> **Status:** Planned
> **Theme:** Return structured, precise, context-budget-aware results instead of file paths

---

## Problem

`idx search` currently returns a ranked list of files with matching lines. For a human reading terminal output, this is the right shape. For an AI agent, it is the beginning of a multi-step retrieval chain: the agent receives a file path, reads the file, locates the relevant block, and extracts the context it needs. Each step consumes context window budget.

Three specific gaps drive this cost:

1. **No symbol resolution.** BM25 retrieves documents — it cannot distinguish a function definition from a call site. An agent searching for `SearchCommandService` may receive ten files where the name appears, but only one contains the type definition. The agent must open and scan each file to find it.

2. **Results are file-granular, not block-granular.** A 600-line file with one relevant function forces the agent to load the entire file or make a second scoped query. There is no way to ask idx to return only the relevant code block.

3. **No context budget control.** Agents operating under tight context limits have no way to request a result set bounded by token count rather than file count. `--size 5` limits files, not tokens.

---

## What we're building

### Symbol-aware search

Index code symbols separately from the BM25 content corpus using tree-sitter. Symbols include function and method declarations, type definitions, interface declarations, and struct fields.

```bash
# find the definition of a specific type
idx search --symbol "SearchCommandService"

# find all implementations of an interface
idx search --symbol "RemoteIndexSearcher" --symbol-kind interface

# combine symbol search with path filter
idx search --symbol "Run" --path internal/features/search
```

The symbol index stores the declaration kind (`func`, `type`, `interface`, `struct`), the containing file, and the line range. Results rank definitions above call sites and separate them in output.

**Implementation note.** tree-sitter grammars are embedded for Go, TypeScript, Python, and Rust at launch. Additional grammars can be added without schema changes. The symbol index is stored as a separate sidecar alongside the BM25 index and rebuilt incrementally on sync.

### `--chunk` flag for `idx search`

Instead of returning a file path and matching lines, `--chunk` extracts the smallest enclosing syntactic block (function body, struct definition, method) and returns it directly.

```bash
# return the function body that contains the match, not just the file path
idx search "popularity boost" --chunk

# limit chunk size to avoid oversized blocks
idx search "popularity boost" --chunk --chunk-lines 60
```

When a match falls inside a function, `--chunk` returns from the function signature to its closing brace. When a match falls at the top level (e.g. a package-level constant), it returns the surrounding declaration. Chunks are annotated with their file path and line range so agents can reference them precisely.

`--chunk` requires tree-sitter support for the target file type. For unsupported file types, it falls back to the `--context N` line-window behavior with a warning.

### `idx context <query>`

A higher-level command that assembles a ready-to-use context package: the most relevant files and their key blocks, bounded by an estimated token budget.

```bash
# assemble up to ~40k tokens of context for a query
idx context "auth middleware token validation" --budget 40000

# emit as JSON for direct injection into an agent prompt
idx context "rate limiter" --budget 20000 --format json
```

Internally, `idx context` runs a search, ranks results, then iteratively adds chunks to the package until the budget is reached. Chunks are selected greedily by rank and deduplicated. The output includes file paths, line ranges, and content — structured so an agent can inject it directly into a prompt without further processing.

Token estimation uses a character-to-token approximation (÷4) by default. A `--tokenizer` flag accepts `cl100k` or `o200k` for more accurate counts when the target model is known.

## User impact

| Before | After |
|---|---|
| Agents open entire files to locate a definition | `--symbol` returns the definition line range directly |
| Agents receive file paths and must re-read for context | `--chunk` returns the relevant code block in one query |
| No way to bound results by context budget | `idx context --budget N` assembles a token-bounded package |
| BM25 conflates definitions with call sites | Symbol index separates declaration rank from usage rank |

---

## Success criteria

- `idx search --symbol "T"` returns the declaration line for type `T` as the first result in any indexed Go file.
- `--chunk` returns a syntactically complete block (parseable by the target language) for every Go, TypeScript, Python, and Rust file in the test suite.
- `idx context --budget 20000` returns a package whose total character count does not exceed `20000 × 4 = 80000` characters.
- Symbol index is rebuilt incrementally on `idx sync` — a change to one file does not trigger a full symbol re-index.
- `--chunk` on an unsupported file type emits a warning and falls back to line-window output without erroring.
