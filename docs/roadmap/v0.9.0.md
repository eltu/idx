# v0.9.0 — AI Integration Layer

> **Status:** Released — [v0.9.0](../releases/v0.9.0.md), June 26, 2026
> **Theme:** Close the gap between what the CLI offers and what agents actually use

---

## Problem

idx already ships a Claude skill that instructs agents to use `idx search` instead of grep. But the integration has accumulated technical debt and a critical blind spot: file reading.

Three concrete issues block reliable agent adoption today:

1. **Stale skill flags.** `--agent-compact` is deprecated in the CLI (replaced by `--compact`), but every example in `SKILL.md` still references the old name. Agents running the deprecated flag get a deprecation warning in output that pollutes their context window.

2. **Extinct commands in the reference sheet.** `idx-commands.md` documents `idx daemon enable/disable`, `idx daemon status`, and `idx watch` — all removed in v0.6.0 and v0.8.0. An agent that follows this reference will invoke commands that no longer exist.

3. **`idx read` is absent from the skill.** Agents read source files using `cat`, `head`, `tail`, or the editor's built-in Read tool. None of these route through idx, so the read log stays empty and the popularity signal (ADR 0017) never accumulates. The ranking improvement that should reward frequently-read files never fires.

---

## What we're building

### Skill: fix stale references

- Replace every occurrence of `--agent-compact` with `--compact` in `SKILL.md` and `idx-commands.md`.
- Remove `idx daemon enable/disable` and `idx watch` from the command reference.
- Update `idx daemon status` → `idx agent status` throughout.
- Fix documentation links that point to the now-renamed Daemon feature page.

### Skill: add `idx read` as the canonical file reader

Add an explicit rule to the skill: agents must use `idx read <path>` instead of `cat`, `head`, `tail`, or the built-in Read tool when reading repository files.

**Why this matters.** Every `idx read` call appends an entry to the read log at `.idx/read_log.idx`. The search ranking pipeline consumes this log to apply a popularity boost — files read more frequently by the agent rank higher in future searches. If agents bypass idx for file reading, the boost never fires and the signal never compounds across sessions.

`idx read` gains a `--compact` flag that strips the decorative header and outputs raw file content, making it suitable for agent pipelines and shell redirects.

### Skill: automated drift detection

Add a CI check that parses flag and command names from the skill's Markdown files and validates them against the actual CLI `--help` output. Any flag or command that exists in the skill but not in the CLI fails the build. This prevents the stale-reference problem from recurring after future releases.

### Skill renamed from `idx-search` to `idx`

The installed skill directory is renamed from `idx-search` to `idx` for every supported editor (`claude`, `cursor`, `copilot`), giving the skill a name that matches the CLI binary itself.

### Project-level enforcement for `idx skills install claude`

Beyond installing the skill file, `idx skills install claude` now also configures the project's `.claude/settings.json` with two enforcement hooks so agents cannot silently bypass idx:

- **`PreToolCall` hook** (`~/.claude/idx-block.sh`) — blocks `grep`, `rg`, `ag`, `cat`, `head`, `tail`, and similar shell tools at the Bash layer, redirecting the agent to `idx search` / `idx read`.
- **`UserPromptSubmit` hook** (`~/.claude/idx-context-hook.sh`) — re-injects the enforcement rules as context on every turn, so they stay active even after the skill file scrolls out of the context window.

`CLAUDE.md` is never modified; both hooks are versioned as embedded assets and installed idempotently (ADR 0023).

## User impact

| Before | After |
|---|---|
| Agents occasionally invoke deprecated flags, polluting output | All skill examples use current flag names |
| Agents read files with `cat` — read log stays empty | Agents route reads through `idx read` — popularity signal accumulates |
| Skill silently drifts from CLI after each release | CI catches drift before it ships |
| Nothing stops an agent from bypassing the skill and using `grep`/`cat` directly | Project-level hooks block bypass attempts at the Bash layer and re-inject the rules every turn |

---

## Success criteria

- `make check` passes with the updated skill assets.
- CI drift-detection check fails when a synthetic stale flag is introduced.
- `idx read --compact` exits 0 and produces raw file content with no header.
- The skill references zero commands or flags that do not exist in the current CLI.
- `idx skills install claude` inside a git repository configures both enforcement hooks in the project's `.claude/settings.json`, idempotently on re-run.

## Dependencies

None. This version has no prerequisites beyond the current v0.8.0 baseline.
