# v1.0.0 — Multi-agent: Worktree Isolation + Hybrid MCP Search

> **Status:** Planned
> **Theme:** Enable multiple agents to work in parallel on the same repository without index collisions, at any codebase scale

---

## Problem

Two independent scaling problems converge at this version.

### Problem 1: the index is a single mutable state

The current architecture maintains one index per project root. When an agent switches branches or another agent checks out a different branch in the same directory, the index resyncs from scratch. The state is shared and mutable — two agents on two branches will corrupt each other's results or trigger redundant resyncs.

As AI-assisted development moves toward parallel workflows (one agent per task, each on its own branch), a single shared index becomes a bottleneck.

### Problem 2: large codebases cannot fit in a local index

A monorepo with hundreds of thousands of files produces an index that is impractical to store and sync locally. Today, idx has no answer for this. Teams either exclude large portions of the repository from indexing (losing recall) or accept the storage cost (losing performance).

---

## What we're building

### Worktree-native isolation

idx adopts `git worktree` as the natural unit of isolation. Each worktree gets its own independent index, agent process, and Unix socket — derived from the worktree's resolved root path.

```bash
# add a worktree for a feature branch (standard git)
git worktree add ../feature-auth feature/auth-overhaul

# start an independent idx agent in that worktree
cd ../feature-auth && idx agent start

# agents in each worktree have isolated state
idx agent status   # in feature-auth: PID 8821
idx agent status   # in main checkout: PID 7103
```

**Branch delta index.** Rather than indexing the full worktree, the local index for each worktree covers only the files that diverge from the branch's merge-base:

```
local index  = git diff $(git merge-base HEAD main)...HEAD
```

Files unchanged from main are excluded from the local index — they are served by the remote baseline (see below). This keeps the local index small regardless of repository size, because it only tracks the active change set.

**Socket isolation.** The Unix socket address incorporates the worktree's canonical path hash, ensuring that `idx search` in `feature-auth/` always routes to the correct agent and never cross-contaminates results with another worktree's state.

**`idx worktree list`** — a new command that enumerates all Git worktrees for the current repository and reports the idx agent status (running / stopped / no index) for each.

```
$ idx worktree list
  main              /Users/dev/myrepo          ✅ agent running  (PID 7103)
  feature/auth      /Users/dev/feature-auth    ✅ agent running  (PID 8821)
  fix/perf          /Users/dev/fix-perf        ⏸ agent stopped
```

### Hybrid MCP search

idx becomes an MCP client. When a remote MCP endpoint is configured, search queries fan out to both the local working-set index and the remote baseline index. Results are merged and re-ranked before being returned to the agent.

**The split criterion is Git state, not file size.** Files modified in the current worktree (`git status`: modified, staged, untracked) are served from the local index. Everything else — the stable, unchanged majority of the codebase — is served from the remote.

**Shadow semantics.** When the same file appears in both the local and remote index, the local result always wins. The developer's local changes are the ground truth; the remote baseline for that file is silently suppressed.

```
search "auth middleware"
  ├── local  → internal/auth/middleware.go   (modified locally) ← used
  ├── remote → internal/auth/middleware.go   (baseline)         ← suppressed
  └── remote → internal/auth/token.go        (stable)           ← used
```

**Configuration.**

```yaml
# .idx.yml
remote:
  mcp_endpoint: mcp://search.company.internal/monorepo
  fallback: local   # if remote is unavailable, search local index only
```

When no `remote` block is configured, idx behaves exactly as today — the remote path is never exercised.

**Architecture.** A new port `RemoteIndexSearcher` is added to the `search` feature package. The `SearchCommandService` receives both the local BM25 backend and an optional `RemoteIndexSearcher`. A new `HybridResultMerger` applies shadow semantics and re-ranks the combined result set. The MCP client adapter implements `RemoteIndexSearcher` and is wired in `cmd/idx` only when a remote endpoint is configured.

## How the two features compose

Worktree isolation and hybrid MCP search are designed to work together, but each is independently useful:

| Scenario | Worktree isolation | Hybrid MCP search |
|---|---|---|
| Single developer, small repo | ✅ prevents index collision across branches | not needed |
| Single developer, monorepo | ✅ prevents collision | ✅ local index stays small |
| Multiple agents, small repo | ✅ each agent has isolated state | not needed |
| Multiple agents, monorepo | ✅ isolated per worktree | ✅ baseline from remote |

The branch delta index (worktree feature) and the remote baseline (MCP feature) use the same underlying primitive: `git diff <merge-base>...HEAD`. The local index is always a delta from a stable reference point, whether that reference is served locally or remotely.

## User impact

| Before | After |
|---|---|
| Two agents on different branches corrupt each other's index | Each worktree has an isolated index and agent process |
| Branch switch triggers full resync | Local index tracks only the branch delta — resync is proportional to the change, not the repo size |
| Monorepos are impractical to index locally | Remote baseline serves stable files; local index stays small |
| No visibility into multi-worktree agent state | `idx worktree list` shows agent health across all worktrees |

---

## Success criteria

- Starting `idx agent` in two different worktrees of the same repository produces two independent processes with independent sockets and no shared index state.
- `idx search` in worktree A returns results from worktree A's index; it does not see worktree B's changes.
- With a remote MCP endpoint configured, `idx search` returns results that include both local and remote files, with local results shadowing remote results for the same file path.
- With the remote MCP endpoint unreachable, `idx search` falls back to local-only results and logs a warning; it does not error.
- `idx worktree list` exits 0 and correctly reports agent status for each Git worktree.
- The branch delta index for a branch with 50 changed files indexes only those 50 files, regardless of total repository size.

## Architectural decisions

This version introduces two new ADRs (next available numbers as of v0.10.2 are 0027+):

- **ADR 0027** — Worktree-scoped index and socket isolation via canonical path hash.
- **ADR 0028** — Hybrid search: git-status-driven local/remote split with shadow semantics; `RemoteIndexSearcher` port; MCP client adapter.
